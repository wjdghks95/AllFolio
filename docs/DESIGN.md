# AllFolio — 디자인 시스템 (DESIGN.md)

**버전:** 1.6.0
**최종 수정:** 2026-08-21
**작성:** ui-ux-designer (Task 007 / T007-8, §6-2는 Task 009에서 확정 · Task 009 재개정에서 개정, §6-3은 Task 010에서 확정, §6-4는 Task 011에서 확정)
**구현 위치:** `frontend/src/index.css`의 `@theme` 블록 (Tailwind v4 CSS-first — `tailwind.config.js`는 만들지 않는다)

이 문서는 확정된 시각 결정의 단일 출처다. 이후 Task(008~011, 018~)에서는 이 문서를 **갱신**만 하고,
이미 폐기한 대안을 근거 없이 다시 꺼내지 않는다.

## 1. 디자인 방향 — "격자지 위의 잉크 (Ink on graph paper)"

AllFolio가 답하는 질문은 하나다. **"추가로 사면 내 평단은 어디로 가는가."**
그 답은 늘 차트 위에 그어지는 한 줄의 수평선(F007 평단가 라인)으로 나타난다.
그래서 이 서비스의 시각 언어는 **모눈종이 위에서 손으로 계산하는 화면**이다 —
값은 등폭으로 자리수를 맞춰 세로 정렬되고, 기준선은 점선 한 줄로 그어진다.

브랜드 액센트 색을 따로 두지 않는다. **유채색은 정보일 때만 등장한다**(손익, 시스템 상태).
장식으로 쓰이는 색이 없기 때문에 화면에 뜬 색은 전부 읽어야 할 신호다.

## 2. 팔레트

### 2-1. 무채 램프 — 종이와 잉크

| 토큰 | hex | 용도 | 선택 이유 |
|---|---|---|---|
| `--color-grid` | `#EFF2F1` | 앱 배경 | 순백도 크림도 아닌 **청록기 도는 회색**. 모눈종이/제도지의 색이고, 위에 얹히는 흰 카드가 "계산 용지"로 떠 보이게 한다. 크림(#F4F1EA 계열)은 의도적으로 피했다(§7 참조) |
| `--color-surface` | `#FFFFFF` | 카드·입력 표면 | 배경과 명도 차 하나만으로 층을 나눈다. 그림자를 쓰지 않는 이유이기도 하다 |
| `--color-rule` | `#D3DAD8` | 경계선·구분선·리더 점선 | 배경과 같은 청록 계열이라 선이 튀지 않는다 |
| `--color-ink-soft` | `#56636B` | 보조 텍스트·라벨·힌트 | `--color-grid` 위 대비 **5.5:1** (WCAG AA 4.5:1 통과) |
| `--color-ink` | `#11161A` | 본문·제목·primary 액션 | 순수 검정(#000)이 아니라 **푸른기 도는 먹**. 종이색과 함께 인쇄물 톤을 만든다 |

### 2-2. 손익 축 — 한국 증권 관례

| 토큰 | hex | 의미 |
|---|---|---|
| `--color-gain` | `#D92E22` | 상승 · 이익 |
| `--color-loss` | `#1552D6` | 하락 · 손실 |

**왜 상승이 빨강인가.** 타깃 사용자는 증권사 앱·거래소 앱을 이미 3개 이상 쓰는 한국 개인 투자자다
(PRD 「핵심 정보」). 그 앱들이 전부 상승=빨강/하락=파랑이므로, 서양식(상승=초록)을 쓰면
**같은 자산을 두 앱에서 보고 반대로 읽는 사고**가 난다. 관례를 따르는 쪽이 안전하다.

**색만으로 구분하지 않는다.** `formatSignedAmount()`가 반환하는 `text`에는 항상 부호(`+`/`−`)가 붙고,
화면에서는 여기에 방향 표식(▲/▼)을 함께 붙인다. 적록색약·전색맹 사용자도 부호와 형태로 읽을 수 있다.
`tone`만 보고 색을 칠하는 마크업은 금지한다.

### 2-3. 시스템 상태 축 — 손익과 hue를 분리

| 토큰 | hex | 용도 |
|---|---|---|
| `--color-alarm` | `#7A2E52` | error · danger (Alert error, Button danger, Field error) |
| `--color-affirm` | `#2F6B4F` | success (Alert success) |

흰 배경 대비: gain 4.8:1 · loss 6.5:1 · alarm 9.0:1 · affirm 6.3:1 — 모두 WCAG AA(4.5:1) 통과.

**왜 error가 빨강이 아닌가.** 상승=빨강을 채택한 순간, 같은 빨강을 "이익"과 "오류" 두 의미로 쓰면
화면에서 충돌한다. 그래서 error는 채도를 낮추고 자주 쪽으로 민 **먹자주(plum)** 로 분리했다.
gain(`#D92E22`, 밝고 채도 높은 빨강)과 명도·채도가 확연히 달라 나란히 놓여도 구분된다.
success 초록은 "상승"으로 오해될 여지가 없다 — 이 서비스에서 상승은 빨강이기 때문이다.

## 3. 타이포그래피 — 3역할

| 역할 | 폰트 | 쓰는 곳 |
|---|---|---|
| **Body / UI** (`--font-sans`) | `IBM Plex Sans KR` → `system-ui` → `Apple SD Gothic Neo` | 한글 본문, 라벨, 버튼, 제목 |
| **Numeric / Display** (`--font-mono`) | `IBM Plex Mono` → `IBM Plex Sans KR` → `ui-monospace` | 금액·수량·평단가·비중 등 **모든 수치** |
| **Utility / Micro** | `--font-mono` + `text-[11px]` + `uppercase` + `tracking-[0.18em]` | 섹션 에이브로우, 축 라벨, 뱃지 |

**왜 등폭이 숫자의 기본인가.** 이 서비스는 소수 8자리 문자열을 정밀도 손실 없이 다룬다
(ROADMAP 「금융 정밀도 규칙」). 등폭이면 자리수가 세로로 맞아 목록에서 값을 눈으로 비교·검산할 수 있다.
장식이 아니라 기능이다. `font-variant-numeric: tabular-nums`도 함께 건다(`index.css` base 레이어).

**왜 IBM Plex인가.** 한글 핀테크의 사실상 기본값인 Pretendard/Inter 조합을 피하면서도
한글 품질이 확보되고, Sans KR ↔ Mono가 같은 슈퍼패밀리라 페어링이 자연스럽다.
Plex 특유의 각진 공학적 인상이 "계산 도구"라는 제품 성격과 맞는다.

로딩은 `index.html`의 Google Fonts `<link>` + `display=swap`. 폴백 스택을 명시해 폰트 실패 시에도
레이아웃이 무너지지 않는다.

### 타입 스케일

| 용도 | 크기 / 굵기 |
|---|---|
| 히어로 총액 (값 있음) | `text-[32px]` → `sm:text-[42px]`, `font-mono`, `font-semibold`, `tracking-tight`, `leading-none`, `text-ink`. **화면당 한 번만** 쓴다(§6-2) |
| 히어로 총액 (값 없음) | `text-[22px]` → `sm:text-[26px]`, `text-ink-soft` + 옆에 상태 표식. 42px짜리 `—` 하나는 "값이 없다"가 아니라 "화면이 깨졌다"로 읽힌다 — 근거는 §6-2 「히어로의 두 상태」 |
| 페이지 제목 (h1) | `text-2xl` → `sm:text-3xl`, `font-bold`, `tracking-tight` |
| 섹션 제목 (h2) | `text-lg`, `font-semibold`, `tracking-tight` |
| 카드 제목 | `text-sm`, `font-semibold`, `tracking-tight` |
| 본문 | `text-[15px]`, `leading-6` |
| 입력 값 | `text-[15px]` (iOS 자동 확대 방지 하한 16px보다 작지만, 입력은 `h-11`로 터치 타깃 확보) |
| 라벨 | `text-[13px]`, `font-medium`, `text-ink-soft` |
| 힌트·에러·캡션 | `text-xs`, `leading-5` |
| 에이브로우·뱃지 | `text-[11px]`, `font-mono`, `tracking-[0.18em]` |

### 한국어 조판

`body { word-break: keep-all; overflow-wrap: break-word; }`
한국어는 어절 단위로 끊어야 읽힌다. 좁은 화면에서 낱말이 쪼개지는 것을 막고,
끊을 곳이 없는 긴 문자열(티커·URL)은 `overflow-wrap`이 받아낸다.

## 4. 간격 · 라운딩 · 모션

- **간격:** Tailwind 기본 4px 스케일. 배경 격자와 플롯 격자 모두 **24px 모듈**(= 4px × 6)로 맞춘다.
  카드 내부 패딩 `px-5 py-4`, 카드 사이 `gap-4`, 섹션 사이 `mt-10`.
- **라운딩 2단계만 둔다.**
  - `--radius-control: 6px` — 버튼·입력·Alert·뱃지
  - `--radius-card: 10px` — 카드·다이얼로그
  - 그 외 값(특히 `rounded-xl` 이상)은 쓰지 않는다. 각짐(0px)도 쓰지 않는다 — 제도지 톤은 유지하되 소프트웨어로 읽혀야 한다.
- **그림자를 쓰지 않는다.** 층은 배경/표면의 명도 차와 1px 경계선으로만 만든다. 유일한 예외는 다이얼로그 backdrop(`bg-ink/45`).
- **컨테이너:** 본문 `max-w-3xl`(768px), 인증 화면 `max-w-sm`. 모바일 좌우 여백 `px-5`.
- **터치 타깃:** 버튼·입력 높이 `h-11`(44px).
- **모션:** 색·경계선 전이 150ms만 쓴다. 페이지 진입 애니메이션 없음.
  `prefers-reduced-motion: reduce`에서 모든 transition/animation을 0.01ms로 무력화한다(`index.css`).
- **포커스:** `:focus-visible { outline: 2px solid var(--color-ink); outline-offset: 2px; }`를 전역 기본값으로 둔다.
  컴포넌트별로 포커스 링을 지우지 않는다.

## 5. 시그니처 — 평단선 (The average line)

**무엇인가.** 2px 점선 수평선 + 선 오른쪽 끝에 붙는 등폭 알약 라벨. 차트의 가격축 관례 그대로다.
현재 평단은 잉크색, 시뮬레이션 결과는 손익색으로 그리고, 두 선 사이에 변화량(▼ −1,667)을 둔다.

**왜 이것인가.** 평단가 수평선은 F007의 실제 화면 요소이자 F006 시뮬레이터가 답하는 값 그 자체다.
장식으로 만든 모티프가 아니라 제품의 핵심 기능을 그대로 그린 것이라, 다른 가계부·지출 관리 앱에는
붙일 곳이 없다.

**규칙 — 점선은 이 기준선에만 쓴다.**
- 일반 구분선은 실선(`border-rule`).
- 예외 하나: 값 목록의 **리더 점선**(라벨과 값을 잇는 `border-dotted`)은 dotted(원형 점)로 dashed와 구분되며,
  "같은 행의 라벨과 값을 잇는다"는 다른 역할을 한다.
  단 **행이 2개 이상 쌓여 오른쪽에 값 열이 실제로 생길 때만** 쓴다. 한 줄짜리에 걸면 이을 열이 없어
  빈 줄만 하나 더 그리는 셈이다(Task 009 재개정, §6-2 「합계 카드」 참조).
- 그 밖의 어떤 곳에도 dashed 테두리를 쓰지 않는다.

**보조 장치 — 격자.** 배경(`body`)에 24px 격자를 잉크 4%로, 차트 플롯 영역(`.plot-grid` 유틸리티)에
잉크 7%로 깐다. 평단선이 "격자 위에 그어진 기준선"으로 읽히게 하는 최소한의 배경 서사다.

## 6. 컴포넌트 규약 (T007-6 6종 + Task 010 추가분)

| 컴포넌트 | 시각 규약 |
|---|---|
| **Button** | `h-11`, `rounded-control`. primary=잉크 솔리드 / secondary=흰 배경+`border-rule` / danger=`alarm` 솔리드. disabled는 `opacity-40` + hover 무효(`hover:not-disabled:`) |
| **Field** | 라벨(13px, ink-soft) → 컨트롤 → 힌트 → 에러 순. 에러는 `alarm` 색 + ⚠ 아이콘(형태 신호). 아이콘은 텍스트 노드가 없는 `<svg>`라 `aria-describedby` 대상의 `textContent`가 문구와 정확히 일치한다 |
| **TextField** | `aria-[invalid=true]`일 때 테두리 `alarm` + 배경 4% 틴트. `inputMode`가 `decimal`/`numeric`이면 **등폭 + 우측 정렬**로 전환한다 |

### 6-1. 인증 화면 골격 (Task 008에서 확정)

`AuthLayout`(`max-w-sm`, 수직 중앙) 안에서 로그인·회원가입은 같은 골격을 쓴다.
**워드마크 → h1 → (한 줄 설명) → 폼(`mt-8`, `gap-4`) → 실선 구분선 → 반대편 화면 링크(`mt-8 pt-5`).**
한 줄 설명은 회원가입에만 둔다 — 로그인은 재방문 화면이라 서비스를 다시 설득할 필요가 없고,
h1 바로 아래에 폼이 오는 편이 더 빠르게 느껴진다.

- **워드마크.** 인증 화면에는 `AppLayout` 헤더가 없으므로 여기서만 페이지 상단에 브랜드를 세운다
  (`text-base font-bold tracking-tight` — AppLayout 헤더 로고와 동일 규격).
- **카드로 감싸지 않는다.** 입력 표면(흰색)이 격자지 배경 위에 그대로 떠서 이미 "계산 용지"로 읽힌다.
  흰 카드 위에 흰 입력을 얹으면 그 층이 사라진다.
- **점선을 쓰지 않는다.** 시그니처(평단선)는 §5대로 예약어다. 인증 화면의 구분선은 실선 `border-rule` 하나뿐이다.
- **제출 버튼은 진행 중 라벨을 바꾼다.** `로그인` → `로그인 중`, `회원가입` → `회원가입 중`.
  버튼 라벨·화면 제목·반대편 링크가 모두 같은 단어를 쓴다(한 흐름 = 한 어휘).
- **인라인 링크.** `font-medium text-ink underline decoration-ink-soft/60 underline-offset-4`,
  hover에서 `decoration-ink`. 링크를 색으로만 구분하지 않기 위해 밑줄을 기본으로 둔다
  (Tailwind preflight가 `a`의 색·밑줄을 상속으로 지워 링크가 본문과 구분되지 않는 문제도 함께 막는다).

### 6-2. 목록 화면 골격 (Task 009에서 확정 · Task 009 재개정에서 개정)

총 자산 홈(F005, 경로는 `/portfolio`)이 이 앱의 첫 **데이터 목록** 화면이라 여기서 목록 규약을 정한다.
이후 목록성 화면(자산 목록·거래 내역 등)은 이 골격을 따른다.

**화면 골격.** 제목 줄(`h1` + 페이지 액션) → 합계 카드(`mt-6`) → 장부 묶음(`mt-10`, 장부 사이 `space-y-4`).
화면은 **한 장짜리 목록이 아니라 나란히 놓인 장부 여러 장**이다 — 합계 / 투자 자산 / 현금 자산.

**페이지 레벨 액션은 제목 줄에 세운다 (Task 009 재개정).**
`자산 등록`은 투자 자산에도 현금 자산에도 속하지 않는 **화면 전체의 액션**이라, 어느 그룹 머리글 안에도
넣지 않는다. 그렇다고 합계 카드와 첫 장부 사이에 혼자 두면 위아래 여백이 똑같이 벌어져
**버튼 하나짜리 세 번째 섹션**으로 읽힌다. `h1`과 같은 줄(`flex items-center justify-between`)에
우측 정렬로 세우면 "이 화면의 액션"이라는 뜻이 자리로 그대로 읽히고, 세로 공간도 90px 돌려받는다.
375px에서도 `총 자산`(24px) + `h-11` 버튼이 한 줄에 들어간다.
빈 상태는 예외다 — 그때는 버튼이 화면의 주인공이라 카드 안 가운데에 남긴다.

- **자산 그룹은 "장부 한 장" 단위로 나눈다 (Task 009 재개정).** 투자 자산(STOCK·COIN)과
  현금 자산(CASH)은 성격이 달라 같은 열에 섞어 읽을 값이 아니다(현금에는 평단가·손익이 없다).
  각 그룹은 **자기 머리글을 가진 독립한 장부 한 장**으로 두고, 머리글은 합계 카드와 **같은 규격**
  (`border-b border-rule px-5 py-3.5`, 제목 `text-sm font-semibold`)을 쓴다.
  - **제목을 격자지 배경 위에 띄우지 않는다.** 배경 위 `text-lg` h2 + 목록 표면 조합은 두 그룹이
    똑같이 반복돼 "같은 목록이 두 번" 나오는 것처럼 보였다. 제목을 표면 안으로 넣으면
    각 그룹이 한 장의 문서가 되고, `합계`와 같은 머리글 규격이라 세 장이 한 벌로 읽힌다.
  - **간격이 위계를 말한다.** 두 장부 사이는 카드 간격(`space-y-4`), 장부 묶음과 합계 카드 사이는
    섹션 간격(`mt-10`). 간격의 대비(16px ↔ 40px)가 "총액 → 그 내역 두 장"이라는 구조를 만든다.
  - **건수는 제목 바로 옆에 붙인다.** `투자 자산 4건`. 숫자만 `font-mono`, 단위 `건`은 본문 자면.
    맨숫자(`4`)는 값으로 오독되므로 단위를 붙인다. 머리글 오른쪽 끝으로 보내지 않는다 —
    바로 아래 `수량`·`›`와 미세 라벨이 세로로 겹쳐 쌓이고, 넓은 화면에서는 제목과 700px 떨어져 홀로 뜬다.
  - **항목이 1건이어도 형식을 줄이지 않는다.** `현금 자산 1건`도 머리글 + 표면을 그대로 쓴다.
    건수는 사용자가 자산을 등록·삭제할 때마다 바뀌는 값이라, 건수에 따라 형태가 달라지면
    **같은 화면이 며칠 사이에 다른 화면으로 보인다.** 그룹의 형태는 그룹이 존재하느냐로만 갈린다
    (0건이면 그 장부 자체를 렌더하지 않는다 — 빈 머리글만 남겨두지 않는다).
  - `<section aria-label={그룹명}>`으로 이름 있는 랜드마크를 만든다(합계 카드와 동일한 취급).
    안쪽 `<h2>`가 같은 이름을 반복하지만, 보조기술 사용자가 그룹 단위로 건너뛸 수 있는 편이 낫다.
- **행마다 카드를 두지 않는다.** 한 장의 표면(`rounded-card border border-rule bg-surface`) 안에서
  `divide-y divide-rule` 실선으로만 나눈다. 카드를 겹쳐 쌓으면 테두리가 행마다 반복돼
  **열의 자리수가 세로로 이어져 보이지 않는다** — 등폭 숫자를 쓰는 이유(§3)가 사라진다.
  이 표면은 `Card` 컴포넌트를 쓰지 않는다. `Card`의 본문 패딩(`px-5 py-4`)이 행을
  가장자리까지 채우는 것을 막기 때문이다.
- **컬럼 헤더 행을 두지 않는다.** 값마다 자기 라벨을 달고 다닌다. 헤더는 (1) 모바일 단일 컬럼과
  같이 갈 수 없고, (2) Phase 2에서 값이 비어 있는 열(평가금액·평가손익)까지 헤더로 광고하게 된다.
- **한 행 = 이니셜 배지 + 신원 블록 + 수치 블록.**
  - 이니셜 배지: `h-9 w-9 rounded-full bg-ink/8`, 등폭 12px. 행의 **첫 번째 자식**으로 두고
    신원 블록 밖에 세운다(신원 블록 안에 넣으면 이름 칸을 48px 잡아먹어 메타 줄이 2줄로 접힌다).
  - 신원: 이름(`text-[15px] font-semibold`) 위, 메타(`티커 · 유형 · 통화`, `text-[11px] text-ink-soft`,
    티커·통화만 등폭) 아래. 서버 enum(`STOCK`/`COIN`/`CASH`)은 화면에 내보내지 않고 주식·코인·현금으로 바꾼다.
  - 수치: `<dl>` **3칸(평가금액 · 손익 · 수량)**. 나머지(평단가·취득원가·비중)는 행을 눌러 들어가는
    자산 상세(Task 011)가 전부 보여준다 — 목록 행은 "무엇을 얼마나 갖고 있나"만 답한다.
- **이니셜 배지 규칙 (Task 009 추가분).** 로고 이미지는 쓰지 않는다 — 외부 이미지 호스팅도, 로고 API도
  이 서비스의 범위가 아니다. 대신 티커를 등폭 이니셜로 새긴 무채 배지를 쓴다.
  - **글자.** 티커가 라틴 문자로 시작하면 앞 2글자 대문자(`BTC → BT`, `AAPL → AA`).
    숫자로 시작하는 국내 종목코드는 앞 2글자가 `00`이 되어 종목을 구분하지 못하므로 **이름의 첫 글자**를
    쓴다(`005930 삼성전자 → 삼`). 같은 종목을 중복 등록하면 배지도 같다 — 그것이 사실이다.
  - **색.** 자산 유형별 색도, 티커 해시 색도 쓰지 않는다. 배지는 순수 장식이고 §2-3에서
    **유채색은 정보일 때만** 쓰기로 했다. 여기서 색을 쓰면 손익 빨강/파랑과 같은 층위로 읽힌다.
    채움은 `bg-ink/8` 한 가지 — 흰 행에서도, `hover:bg-grid`가 깔린 행에서도 한 단계 어둡게 남는다.
  - **테두리를 두르지 않는다.** 행 구분 실선 옆에 원형 테두리까지 더하면 선이 두 겹으로 늘어난다.
    채움만으로 층이 생긴다(§4).
  - `aria-hidden="true"`. 이니셜의 출처인 티커·이름이 바로 옆 텍스트로 이미 읽히므로 보조기술에는 중복이다.
- **폭에 따른 접힘.** 가로 스크롤 테이블을 쓰지 않는다(§8 「신문형 다단」 폐기 사유와 같다).
  - **좁은 화면:** 1열. 라벨 왼쪽 / 값 오른쪽 한 줄(`flex justify-between`).
    3줄 × 24px 피치라 배경 격자(§4의 24px 모듈)와 그대로 맞는다.
  - **`sm:` 이상:** 신원 블록이 남는 폭을 전부 가져가고(`sm:flex-1`), 수치 블록은 **폭을 고정해
    오른쪽에 붙인다**(`sm:w-96 sm:shrink-0`, 3열 `sm:gap-x-4`). 라벨 위 / 값 아래로 쌓고 우측 정렬.
    수치 블록에 `flex-1`을 주면 남는 폭이 3등분돼 칸마다 빈자리가 흩어지고, 값이 `—`뿐인 Phase 2에서
    행이 성글게 벌어져 보인다. 폭을 고정하면 세 값이 오른쪽에서 하나의 덩어리로 뭉치고,
    남는 폭은 이름 칸이 가져간다(128px → 약 230px, 긴 종목명이 접히지 않는다).
    `w-96`(384px)은 열당 약 117px — 시세 연동 후 들어올 10자리 원화 금액(약 101px)까지 받는 치수다.
  - 어느 폭에서든 **값은 오른쪽 기준선에 붙는다.** 목록 전체의 숫자가 하나의 세로선에 정렬된다.
  - 값에 `whitespace-nowrap`을 건다. **금액은 어떤 폭에서도 숫자 중간에서 줄바꿈되면 안 된다.**
    좁은 화면에서 2열로 쪼개지 않기로 한 것도 COIN(소수 8자리, 19자 이상) 값이 칸을 넘겨
    `82,000,000.000000 / 00`처럼 잘렸기 때문이다.
- **행 이동 표식.** 오른쪽 끝 `›`(`aria-hidden`), 세로로는 **이름 줄에 맞춘다**(`self-start`).
  가운데 정렬하면 우측 정렬된 숫자열 한가운데로 끼어든다. 호버는 `hover:bg-grid` 150ms.
  포커스 링은 표면이 `overflow-hidden`이라 밖으로 나가면 잘리므로 `focus-visible:-outline-offset-2`로
  안쪽에 그린다 — 지우는 것이 아니라 위치만 옮긴다(§4).
- **손익 표기.** `tone` → 색(`TONE_CLASS`)과 방향 표식(`TONE_MARK`: gain `▲` / loss `▼`)을 함께 쓴다.
  방향이 없는 `flat`(0)·`unknown`(—)에는 표식을 붙이지 않는다. 표식은 `aria-hidden` —
  읽어야 할 신호는 이미 부호(+/−)에 들어 있다.

**비어 있는 값을 사고로 보이게 두지 않는다.** Phase 2에서는 평가금액·평가손익이 전부 `null`이라
행마다 `—`가 2개씩 뜨고, 합계 카드에는 숫자가 **한 개도** 남지 않는다. 카드 아래에 그 이유를 한 번 밝힌다 —
"통화가 다른 자산은 KRW로 환산해 이 총액에 더합니다. 평가금액·평가손익은 시세를 연동하면 채워집니다."
사과하지 않고 사실과 조건만 말한다(§7). `Alert`를 쓰지 않는 이유는 이것이 액션에 대한 피드백이 아니라
화면에 상시 붙는 맥락이기 때문이다. (`환전`이 아니라 `환산` — 실제로 돈을 바꾸는 것이 아니라
평가액을 환율로 옮겨 적는 것이다.)

**합계 카드 — 히어로의 두 상태 (Task 009 재개정).** 화면에 들어와서 가장 먼저 읽어야 할 숫자는
**평가금액 총액**(`totalEvaluationKrw`) 하나다. 통화별 취득원가 병기 블록은 Task 009 재개정에서 걷어냈다 —
Task 006 결정으로 서버가 KRW 환산 총액 하나만 내려주므로 통화를 나눠 적을 이유가 사라졌다.

- **값이 있을 때(Phase 3~).** 라벨(`평가금액`, 13px) → 히어로(§3 타입 스케일, 32/42px 잉크).
  히어로는 화면당 하나다. 두 개를 세우면 어느 쪽도 히어로가 아니다.
- **값이 없을 때(Phase 2).** 같은 자리에 `—`를 **22/26px, `ink-soft`** 로 줄여 놓고,
  바로 옆에 상태 표식 `시세 연동 전`(알약, `bg-ink/8`, `rounded-control`, 11px)을 붙인다.
  42px짜리 대시 하나가 카드 상단에 떠 있으면 "값이 없다"가 아니라 "렌더가 깨졌다"로 읽힌다.
  **크기를 줄이는 것만으로는 부족하고, 이유를 숫자 옆에서 말해야 한다** — 카드 하단 주석까지
  내려가야 알 수 있으면 그 사이 동안 화면은 고장 난 상태로 보인다.
  값의 유무는 마크업의 삼항 하나(`hasTotalEvaluation`)로 가른다. 없는 숫자를 지어내지 않는다 —
  `null`은 끝까지 `null`로 둔다.
- **상태 표식에 에이브로우 자간을 걸지 않는다.** §3의 유틸리티 역할(`font-mono` + `tracking-[0.18em]`)은
  라틴 대문자·숫자 기준이다. 한글에 그대로 걸면 `시 세  연 동  전`처럼 낱자로 흩어진다.
  한글 표식은 본문 자면(sans) + 기본 자간 + `font-medium`으로 둔다.
- **보조 지표(평가손익)는 리더 점선을 쓰지 않는다.** 카드에 라벨-값 행이 **하나뿐**이면 리더 점선은
  잇는 역할을 하지 못하고 700px짜리 빈 줄을 하나 더 그린다. 실선 구분선 아래에
  `평가손익` 라벨(13px) + 값을 **왼쪽에 붙여 나란히** 둔다. 리더 점선(§5 예외)은 행이 **2개 이상 쌓여
  오른쪽 값 열이 실제로 생길 때만** 쓴다 — 자산 상세(Task 011)가 그 자리다.

**빈 상태.** 목록 표면 대신 `Card` 한 장에 가운데 정렬로 사실 한 줄(`등록된 자산이 없습니다.`) +
무엇을 얻는지 한 줄 + 주 액션 버튼을 둔다. 빈 화면은 행동으로의 초대다.
점선 테두리(dashed)로 자리를 표시하지 않는다 — dashed는 시그니처 전용이다(§5).

### 6-3. 폼 화면 골격 (Task 010에서 확정)

자산 등록(F001, 경로는 `/assets/new`)이 이 앱의 첫 **여러 필드 폼** 화면이라 여기서 폼 규약을 정한다.
이후 폼성 화면(자산 수정·시뮬레이터 입력 등)은 이 골격을 따른다.

**화면 골격.** `h1` → 폼(`mt-8`, `max-w-md`) → 묶음 제목 + 필드(`gap-4`) → 다음 묶음(`mt-8`) →
제출 버튼(`mt-8`, 폼 폭 전체).

- **폼은 본문 폭을 다 쓰지 않는다.** 본문 컨테이너는 `max-w-3xl`(768px)이지만 입력 칸은
  `max-w-md`(448px)로 묶는다. 1280px에서 6자짜리 티커 칸이 728px로 늘어나면 라벨과 값이 멀어지고
  유형 토글의 세 칸이 텅 빈다. **폭 제한은 입력 폼에만 건다** — 목록·카드는 §6-2대로 본문 폭을 그대로 쓴다.
- **필드는 두 묶음으로 나눈다.** `자산 정보`(유형·티커·종목명·통화) / `보유 정보`(수량·평단가).
  6칸을 한 줄로 세우면 375px에서 라벨-입력이 여섯 번 반복되는 벽이 된다.
  필드 사이 16px, 묶음 사이 32px — **간격의 대비가 곧 구조다**(§6-2와 같은 원리. 폼에서는
  섹션 간격 40px 대신 32px을 쓴다. 세로로 긴 화면이라 스크롤을 아낀다).
- **묶음 제목은 장부 머리글과 같은 규격**(`text-sm font-semibold tracking-tight text-ink`, §6-2).
  필드 라벨(13px·`font-medium`·`ink-soft`)과 크기·굵기·색 세 축이 갈려 "또 하나의 라벨"로 읽히지 않는다.
- **필드 순서는 "무엇을 → 얼마나".** 자산 유형이 맨 위에 오는 이유는 유형이 **아래 칸의 입력 예시와
  평단가 칸의 존재 여부를 바꾸기 때문**이다. 뒤에 두면 이미 채운 값을 다시 읽게 만든다.
- **통화는 자유 텍스트가 아니라 선택이다 (Task 010 수정, 코드리뷰 반영).** PRD F001의 "통화(KRW/USD)
  선택"을 따라 KRW/USD 2지선다로 고정한다 — USD 외 통화 확대는 PRD 비목표다. 자산 유형과 같은
  `SegmentToggle`(위 §6 컴포넌트 규약)을 그대로 쓴다 — 선택지 개수만 다를 뿐 "몇 안 되는 값 중 하나를
  고르는 한 필드"라는 성격이 같아, 자유 텍스트(`TextField`)로 두면 유형은 선택인데 통화만 오타가 나는
  비대칭이 생긴다. 기본값은 `KRW`(자산 유형이 `STOCK`으로 시작하는 것과 같은 패턴).
- **조건부 필드는 빈자리를 남기지 않는다.** CASH를 고르면 평단가 칸이 사라진다(Task 006 결정).
  그 자리에 **사라진 이유 한 줄**을 같은 폭의 잉크 5% 밴드로 남긴다 —
  "현금은 평단가 없이 수량만 등록합니다."
  - 제출 버튼이 70px 튀어 오르던 점프가 25px로 줄고, 무엇보다 칸이 왜 없어졌는지를 화면이 스스로 말한다.
  - **높이 애니메이션으로 접지 않는다.** §4에서 모션은 색·경계선 전이 150ms로 한정했다.
  - 이 밴드에 `Alert`를 쓰지 않는다. Alert는 액션의 결과(피드백)에 쓰고, 이것은 상시 맥락이다
    (§6-2 합계 카드 하단 주석과 같은 판단).
  - 문구는 검증 메시지(`PRICE_FORBIDDEN_FOR_CASH`)와 **다른 문장**을 쓴다. 검증 메시지는
    "잘못 넣었을 때" 뜨는 말이고, 이 밴드는 "넣을 칸이 없다"는 설명이다.
- **입력 예시(placeholder)는 유형을 따라간다.** 주식 `005930`·`삼성전자` / 코인 `BTC`·`비트코인` /
  현금 `KRW`·`원화 예수금`. 예시가 고정이면 코인을 고른 사람이 티커 칸에서 `005930`을 보게 된다.
  - **수치 예시에 천 단위 쉼표를 넣지 않는다**(`1000000`, `71500`). 쉼표는 실제로 입력하면
    거부되는 문자다(`NUMBER_FORMAT`). 예시는 그대로 따라 칠 수 있는 형태여야 한다.
  - **힌트(hint)는 달지 않는다.** 네 칸 전부에 설명을 붙이면 폼 높이가 1.5배가 되고 정작 읽어야 할
    에러 문구가 묻힌다. 설명은 예시(placeholder)와 검증 에러(§7 — 한계값을 숫자로 밝힌다)가 나눠 맡는다.
- **제출 버튼은 폼 폭을 다 쓴다.** `mt-8 flex flex-col [&>button]:w-full`(§6-1 인증 화면과 같은 패턴).
  라벨은 진입 버튼·화면 제목과 같은 단어를 쓴다 — 총 자산의 `자산 등록` 버튼 → 화면 제목 `자산 등록`
  → 제출 `자산 등록` → 배너 `자산이 등록되었습니다.` **한 흐름 = 한 어휘**(§6-1).
- **취소 버튼을 두지 않는다.** 파괴적이지 않은 폼이라 되돌릴 것이 없고, 헤더 워드마크와 뒤로가기가
  이미 같은 일을 한다. 주 액션 옆의 취소는 시선만 나눠 갖는다.

**안내 배너(flash)의 자리.** 다른 화면에서 넘어오며 실어 보낸 배너(Task 007이 정한 토스트 대체 패턴:
`navigate(path, { state: { flash } })` + `Alert`)는 **본문 맨 위, `h1` 위**에 놓고 아래로 24px 띄운다.

- 제목 아래에 끼우면 위 16px·아래 24px로 여백이 비슷해져 합계 카드와 한 덩어리로 뭉치고,
  §6-2가 정한 제목 아래 리듬(제목 → `mt-6` 합계 → `mt-10` 장부)이 **배너의 유무에 따라 달라진다**.
  제목 위로 올리면 나머지 화면은 배너가 없을 때와 완전히 같은 자리에 놓인다.
- 빈 상태 분기에도 같은 자리를 쓴다. 같은 배너가 화면 상태에 따라 다른 곳에 뜨면 안 된다.
- 배너는 스스로 사라지지 않는다(Task 007 결정). 읽는 속도를 타이머가 정하지 않는다.

### 6-4. 상세 화면 골격 (Task 011에서 확정)

자산 상세(F002·F003·F004·F006·F007, 경로는 `/assets/:id`)는 이 앱에서 **한 화면에 조회·계산·수정·삭제가
전부 들어오는 유일한 화면**이다. 여기서 "여러 성격의 블록을 한 화면에 쌓는 법"을 정한다.

**화면 골격.** 뒤로가기 링크 → 신원 블록(`h1` + 메타 한 줄) → **읽는 묶음**(`mt-8`, 카드 사이 `space-y-4`)
→ **고치는 묶음**(`mt-10`) → 삭제 밴드(`mt-8` + 실선 + `pt-6`).

- **경계는 "저장되느냐"로 긋는다.** 상세 정보·평단가 차트·시뮬레이터는 아무것도 쓰지 않는다
  (시뮬레이터는 ROADMAP대로 DB 미저장). 수정·삭제는 누르면 실제로 바뀌거나 사라진다.
  이 경계가 이 화면의 유일한 위계라, 카드 간격(16px)과 섹션 간격(40px)의 대비로 그린다
  (§6-2·§6-3과 같은 원리 — 간격이 곧 구조다). 다섯 덩어리를 전부 16px로 쌓으면 화면에 위계가 없어지고,
  무엇보다 **읽다가 손이 미끄러져 닿는 자리에 파괴적 액션이 온다.**
- **카드 제목은 명사구로 짓는다.** `상세 정보` / `평단가 차트` / `물타기 시뮬레이터` / `보유 정보 수정`.
  맨동사(`수정`)는 카드 제목이 아니라 버튼 라벨처럼 읽힌다. `보유 정보`는 자산 등록 화면의 두 번째
  필드 묶음 제목(§6-3)과 같은 말이다 — 같은 필드 묶음에는 같은 이름을 쓴다.
- **한 흐름 = 한 어휘 (§6-1).** 카드 제목 `보유 정보 수정` → 제출 버튼 `수정` → 완료 배너
  `자산이 수정되었습니다.` 세 자리가 같은 동사를 쓴다.

**상세 정보 카드 — 라벨-값 나열.**

- **리더 점선(§5 예외)을 쓰는 자리가 여기다.** 라벨 6줄이 세로로 쌓여 오른쪽에 실제 값 열이 생기므로,
  점선이 이을 대상이 있다(합계 카드처럼 한 줄뿐인 경우와 다르다 — §6-2). 행 규격은 `/dev/ui`의
  `ReadRow`와 동일하다: 라벨(14px `ink-soft`) · 점선 리더(`border-dotted border-rule`) ·
  값(`font-mono text-sm font-medium`, 우측 정렬), 행 높이 `py-1.5`.
- **두 묶음으로 나눈다: 내가 적어 넣은 값 / 시세가 채워 넣는 값.**
  위 묶음은 보유수량·평단가·취득원가, 아래 묶음은 평가금액·평가손익·비중. 사이에 실선 하나
  (`mt-2 border-t border-rule pt-2`)를 긋고, 카드 맨 아래에 이유 한 줄을 남긴다 —
  "평가금액·평가손익·비중은 시세를 연동하면 채워집니다."
  - Phase 2에서 아래 셋은 전부 `—`다. 여섯 줄을 한 덩어리로 쌓으면 뒤쪽 세 줄이 **빈 값이 아니라
    고장으로** 읽힌다(§6-2 「비어 있는 값을 사고로 보이게 두지 않는다」와 같은 판단).
  - 주석 문장은 총 자산 합계 카드의 주석과 **같은 어휘**를 쓴다. 같은 이유로 비어 있는 값을
    화면마다 다른 문장으로 설명하지 않는다.
  - 이 구분선은 Phase 3 이후에도 유효하다("내가 적은 값"과 "시세가 만든 값"의 경계는 값이 채워져도
    남는다). 다만 아래 주석 문장은 시세 연동 시점에 걷어낸다(§9).
- **현금은 평단가에 딸린 행을 전부 내린다.** CASH의 `avgPrice=1`은 저장상의 약속이지(ROADMAP 결정 #1)
  사용자가 읽을 값이 아니고, `cost = 1 × quantity`라 취득원가는 보유수량과 **언제나 같은 숫자**다.
  같은 수를 라벨만 바꿔 두 번 적으면 화면이 고장 난 것처럼 보인다. 남는 행은 보유수량 하나 +
  시세 묶음 셋이다.

**평단가 차트 — 이중 평단선 (§5 시그니처의 실제 적용).**

- **현재 평단선은 플롯의 정확한 한가운데(`top-[50%]`)에 고정한다.** 계산할 때마다 기준선이 자리를
  옮기면 기준선이 아니다. 예상선만 방향에 따라 위(`top-[20%]`)나 아래(`top-[80%]`)에 붙는다.
- **평단이 오르면 선도 위로 간다.** 좌표는 여전히 고정값이고 스케일 계산은 하지 않는다(정적 더미).
  다만 **오르는데 아래에 긋는 것**은 가격축에서 유일하게 남아 있는 시각 정보(방향)가 거짓말을 하는
  것이라, `diffTone === 'gain'` 하나로 위/아래 두 좌표 중 하나를 고른다. 값의 크기는 반영하지 않는다 —
  두 선 사이 거리는 어느 경우에도 30%로 같다.
  - `flat`(변화 없음)은 `loss`와 같은 배치를 쓴다. 두 값이 같은데 높이가 다른 것은 부정확하지만,
    이 플롯에는 애초에 눈금도 스케일도 없어 "같은 높이 = 같은 값"이라는 약속 자체가 없다.
    반면 **부호와 반대 방향으로 긋는 것**은 약속을 어기는 쪽이라 급이 다르다.
- **선 행에는 `-translate-y-1/2`를 건다.** `absolute top`은 줄의 윗변을 잡으므로, 보정하지 않으면
  선이 뱃지 높이의 절반(약 11px)만큼 내려앉아 두 선 사이 변화량 라벨과 겹친다
  (375px 코인 화면에서 실측 — 좌표가 아니라 앵커의 문제다).
- **뱃지는 선 오른쪽 끝, 변화량은 두 선 사이 왼쪽.** 뱃지 라벨은 `현재`/`예상` 두 단어로 고정한다.
  변화량에는 색과 함께 부호·▲▼를 붙인다(§2-2).
- **좁은 화면에서는 선이 값에 자리를 내준다.** 뱃지는 `shrink-0`, 점선은 `flex-1`이라
  코인(소수 8자리, 20자 이상)에서는 점선이 90px 남짓까지 줄어든다. 그래도 **값을 자르지 않는다** —
  금액은 어떤 폭에서도 한 줄로 온전히 읽혀야 한다(§6-2).
- **현금은 카드째 렌더하지 않는다.** 평단가가 없는 자산에 평단선을 그으면 시그니처가 뜻을 잃는다.

**시뮬레이터 카드와 수정 카드 — 나란히 놓인 두 폼.**

두 카드는 생김새가 같은 입력 폼이다(라벨 + `h-11` 입력 + 버튼). 무엇이 다른지는 **형태가 아니라
문장으로** 말한다 — 색이나 테두리로 구분하면 §2-3의 "유채색은 정보일 때만" 규칙을 깬다.

- **시뮬레이터 카드 첫 줄에 성격을 밝힌다.** "추가로 사면 평단가가 어디로 가는지 계산합니다.
  결과는 저장되지 않습니다." 두 번째 문장이 아래 수정 카드와의 차이 그 자체다.
- **카드 안 입력도 `max-w-md`(448px)로 묶는다** (§6-3). 카드 폭(768px)을 다 쓰면 6자리 금액 칸이
  700px로 늘어나 라벨과 값이 멀어진다. 오른쪽에 남는 흰 공간은 결함이 아니라 폼의 폭 제한이다.
- **제출 버튼은 폼 폭을 다 쓰지 않는다.** §6-3의 "제출 버튼은 폼 폭 전체"는 **화면 전체가 폼 하나인
  경우**의 규칙이다. 한 화면에 폼이 둘 있는 여기서는 두 버튼(`계산` secondary / `수정` primary)을
  자연 폭으로 두고, 무게 차이는 variant가 낸다.
- **계산 결과는 격자지 색 밴드에 담는다.** `rounded-control border border-rule bg-grid px-4 py-2` 안에
  리더 행 2줄(예상 평단가 · 예상 보유 수량). 흰 표면에 그대로 이어 붙이면 입력의 연장(세 번째·네 번째 줄)로
  읽힌다 — 결과는 입력이 아니라 답이다.

**삭제 — 카드 밖, 실선 아래.**

- 되돌릴 수 없는 유일한 액션이라 카드에 넣지 않는다. 수정 카드에서 `mt-8` 떨어뜨리고 실선 하나를
  그은 뒤 `pt-6` 아래에 세운다. 수정 버튼과 세로로 90px 이상 떨어지고, 사이에 선이 있어 손이 미끄러져
  닿지 않는다.
- **무엇을 위한 버튼인지 한 줄 먼저 말한다** — "더 이상 보유하지 않거나 잘못 등록한 자산을 목록에서
  지웁니다." 자산 유형과 무관하게 성립하는 문장을 쓴다("전량 매도"는 현금 화면에서 말이 안 된다).
  **무엇을 잃는지는 확인 팝업이 말한다** — 같은 경고를 두 번 하면 둘 다 안 읽힌다.
- **확인 팝업 제목은 `{종목명} 삭제`.** 조사(을/를)를 붙이지 않는 이유는 받침에 따라 갈리기 때문이다
  (`삼성전자를` / `비트코인을`). 코드로 조사를 고르느니 명사구로 끊는다.
  description은 ROADMAP 「확정된 설계 결정」 #4의 고정 문구이므로 **변경하지 않는다.**

**없는 자산 — 빈 상태와 같은 골격.**

총 자산의 빈 상태(§6-2)와 같은 모양을 쓴다: `Card` 한 장, `py-6 text-center`, 사실 한 줄
(`자산을 찾을 수 없습니다.`, 15px semibold) + 이유·다음 행동(`ERROR_MESSAGES.ASSET_NOT_FOUND`,
`max-w-xs` 본문) + 가운데 주 액션(`총 자산으로 돌아가기`). 같은 성격의 화면이 서로 다른 모양으로
비어 있으면 안 된다. 이 자리에 `Alert`(error)를 쓰지 않는다 — 액션에 대한 피드백이 아니라
**화면이 통째로 비어 있는 상태**다.

## 7. UI 카피 원칙

`frontend/src/lib/messages.ts`의 문구는 아래 규칙을 따른다(키 구조는 타입과 1:1이라 변경 불가).

- **무엇이 잘못됐는지 + 어떻게 고치는지**를 한 문장에 담는다. → "이메일을 name@example.com 형식으로 입력하세요."
- **사과하지 않는다.** "죄송합니다" 없이 사실과 다음 행동만 말한다.
- **한계값은 숫자로 밝힌다.** "너무 깁니다"(X) → "티커는 20자까지 입력할 수 있습니다"(O).
- **문장부호를 지킨다.** 완결된 문장은 마침표로 끝낸다.
- 예외: `HOLDING_CONFLICT`는 ROADMAP Task 011에서 고정한 문구라 변경하지 않는다.

## 8. 폐기한 대안과 폐기 이유

같은 안을 다시 검토하지 않기 위해 남긴다.

| 폐기안 | 폐기 이유 |
|---|---|
| **크림 배경(#F4F1EA) + 세리프 디스플레이 + 테라코타 액센트** | 현재 AI가 생성하는 디자인의 최빈 기본값. 브리프가 요구하지 않았고, 이 서비스의 "계산 도구" 성격과도 무관하다 |
| **거의 검정 배경 + 형광 그린/버밀리언 단일 액센트 (HTS·트레이딩 터미널 룩)** | 두 번째 기본값이자, 상승 빨강/하락 파랑을 얹으면 형광 액센트와 신호가 충돌한다. Capacitor 하이브리드 앱의 낮 시간 사용 맥락과도 안 맞는다 |
| **헤어라인 룰 + 라운딩 0 + 신문형 다단 레이아웃** | 세 번째 기본값. 모바일 우선(단일 컬럼) 요구와 정면으로 충돌한다. 대신 라운딩을 6/10px로 최소화하는 선에서 제도지 톤만 가져왔다 |
| **보라 그라디언트 + Inter (SaaS 기본값)** | 브랜드가 아니라 프레임워크 기본값처럼 읽힌다. 그라디언트는 금액 옆에서 판독성만 떨어뜨린다 |
| **Pretendard + Inter 페어링** | 품질은 좋지만 한국 프로덕트의 사실상 기본값이라 서비스를 구분해주지 못한다. IBM Plex Sans KR + Plex Mono로 대체 |
| **서양식 손익 색(상승 초록 / 하락 빨강)** | 타깃 사용자가 매일 쓰는 국내 증권·거래소 앱과 반대라 오독 위험이 크다. §2-2 참조 |
| **error를 빨강으로 두기** | 상승(이익) 빨강과 의미가 충돌한다. `alarm`(먹자주)으로 분리 |
| **브랜드 액센트 색을 따로 지정 (틸/골드 등)** | 손익 빨강·파랑, 상태 자주·초록 위에 다섯 번째 유채색을 더하면 "색 = 정보" 규칙이 깨진다. 브랜드 자리는 잉크(무채)가 가져간다 |
| **카드 그림자(elevation) 체계** | 종이/제도지 톤에서 부유하는 그림자는 이물감이 있다. 명도 차 + 1px 선으로 충분했다 |
| **차트 플롯에 좌측 눈금 레일(tick rail) 추가** | 격자 + 평단선 + 가격 뱃지 위에 눈금까지 얹으니 과했다. 시그니처 하나만 남기고 덜어냈다 |
| **시그니처 뱃지를 선의 왼쪽 끝에 배치** | 뱃지 폭이 서로 달라 점선 시작점이 어긋나 보였다. 차트 가격축 관례대로 오른쪽 끝으로 옮겼다 |
| **포트폴리오 목록을 9열 가로 스크롤 테이블로 (Task 009)** | 375px에서 정작 중요한 금액 열이 화면 밖으로 밀린다. 모바일 우선(단일 컬럼) 원칙과 정면 충돌 |
| **포트폴리오 행마다 개별 카드 (Task 009)** | 행마다 테두리가 반복돼 열의 자리수가 세로로 이어져 보이지 않는다. 등폭 정렬(§3)의 이점이 사라진다 |
| **좁은 화면 수치 블록을 2열 그리드로 (Task 009)** | COIN 값(`82,000,000.00000000`, 19자)이 칸 폭(≈128px)을 넘겨 숫자 중간에서 줄바꿈됐다. 1열 라벨-값 한 줄로 바꾸니 높이도 오히려 줄었다(라벨/값을 쌓지 않아도 되므로) |
| **목록 행에도 리더 점선 적용 (Task 009)** | 자산 5건 × 값 6개 = 점선 30줄. 리더는 한 열짜리 라벨-값 목록(합계 카드·상세 화면)에만 남긴다 |
| **비중 칸에 막대 게이지 추가 (Task 009)** | Phase 2에서는 `weight`가 전부 `null`이라 빈 트랙 5개가 로딩 실패처럼 보인다. 시세 연동(Phase 3) 이후 재검토 |
| **행 이동 표식(`›`)을 세로 가운데 정렬 (Task 009)** | 우측 정렬된 숫자열 한가운데로 끼어들어 금액과 충돌했다. 이름 줄에 맞춰 위로 올렸다 |
| **합계 카드에서 통화를 `sm:grid-cols-2`로 동등하게 나열 (Task 009)** | KRW와 USD가 같은 무게라 화면에 "가장 먼저 읽을 숫자"가 없었다. 통화를 합치지 않는 원칙은 유지한 채 자리의 위계만 바꿔 KRW를 히어로로 세웠다 |
| **이니셜 배지를 자산 유형별 색 / 티커 해시 색으로 (Task 009)** | 배지는 정보가 아니라 장식이다. §2-3의 "유채색은 정보일 때만" 원칙을 깨고 손익 신호와 같은 층위로 읽힌다. `bg-ink/8` 무채 한 가지로 고정 |
| **이니셜 배지를 신원 블록(`sm:w-32`) 안에 넣기 (Task 009)** | 배지+간격 48px이 이름 칸을 잡아먹어 메타 줄(`005930 · 주식 · KRW`)이 2줄로 접혔다. 배지를 행의 첫 자식으로 빼서 해결 |
| **신원 블록을 `sm:w-28`로 줄여 수치 열 폭 되찾기 (Task 009)** | 배지가 가져간 48px을 메우려 시도했으나 열당 5px 회복에 그치고 메타 줄이 2줄로 접혔다. 당시엔 `sm:w-32` 유지로 결론냈다(코인 값 19자 ≈ 148px이 149px 열에 들어감). 이후 투자/현금 분리 개편에서 신원 블록이 `sm:flex-1`로 바뀌며 이 폭 제약 자체가 없어졌다 — 수치 블록이 `sm:w-96 sm:shrink-0`로 고정폭이 되어 신원 블록 쪽 폭을 따로 관리할 이유가 사라졌다 |
| **다크 테마 전면 전환 (Task 009 재검토)** | 참고한 증권 앱 스크린샷이 다크였으나, 위의 "거의 검정 배경" 항목과 같은 이유로 다시 폐기했다. 히어로 총액·이니셜 배지 두 패턴만 라이트 테마 안으로 가져왔다 |
| **비중 도넛/파이 차트 (Task 009 재검토)** | `weight`가 Phase 2에서 전부 `null`이라 빈 도넛만 남는다. 막대 게이지와 같은 이유로 Task 023 이후로 미룬다 |
| **세그먼트 토글(시세/평가, 종목별/유형별) · 행별 일간 수익률 (Task 009 재검토)** | PRD F005 스펙에 없고, 일간 수익률은 실시간 시세(Task 021/023) 없이는 채울 데이터 자체가 없다 |
| **값이 없어도 히어로를 42px로 유지 (Task 009 재개정)** | Phase 2 내내 42px `—` 하나가 카드 상단에 떠 있어 로딩 실패로 읽힌다. 값의 유무에 따라 히어로를 두 상태(32/42 잉크 ↔ 22/26 ink-soft + 상태 표식)로 나눴다 |
| **빈 히어로 자리를 취득원가·자산 건수 같은 "있는 숫자"로 채우기 (Task 009 재개정)** | 카드 제목이 `합계`, 라벨이 `평가금액`인 자리에 다른 지표를 끼워 넣으면 라벨과 숫자가 어긋난다. 없는 값은 없는 채로 두고, 왜 없는지만 말한다 |
| **빈 히어로에 스켈레톤(펄스 바) 깔기 (Task 009 재개정)** | 스켈레톤은 "곧 도착한다"는 뜻이다. Phase 2의 `null`은 요청 중이 아니라 **아직 연동하지 않은 상태**라 거짓말이 된다. 정적인 상태 표식으로 대체 |
| **합계 카드의 단일 라벨-값 행에 리더 점선 유지 (Task 009 재개정)** | 행이 하나뿐이라 점선이 이을 값 열 자체가 없다. 라벨에서 640px 떨어진 `—` 하나로 시선만 던져 놓는 꼴이라, 라벨 옆에 값을 붙이는 쪽으로 바꿨다 |
| **한글 상태 표식에 에이브로우 자간(`tracking-[0.18em]`) 적용 (Task 009 재개정)** | `시 세  연 동  전`으로 낱자가 흩어져 읽는 속도가 눈에 띄게 떨어졌다. 자간 규격은 라틴·숫자 전용으로 한정 |
| **수량을 신원 블록(이름·티커 줄)으로 옮기기 (Task 009 재개정)** | 3필드 중 Phase 2에 실제 값이 있는 유일한 칸이 수량이다. 이걸 빼면 수치 블록에 `—`만 남아 행이 더 고장 나 보인다. 수량은 우측 정렬 숫자 열에 남겨 자리수 정렬(§3)을 지킨다 |
| **필드가 3개로 줄었으니 수치 블록도 `flex-1`로 넓게 3등분 (Task 009 재개정)** | 남는 폭이 3등분되면서 칸마다 빈자리가 흩어져 행이 성글게 벌어졌다. 블록 폭을 `w-96`으로 고정해 오른쪽에 붙이고, 남는 폭은 이름 칸에 줬다 |
| **`자산 등록`을 합계 카드와 첫 목록 사이에 단독 배치 (Task 009 재개정)** | 위 `mt-8`·아래 `mt-10`으로 여백이 거의 같아, 페이지 액션이 아니라 **버튼 하나짜리 세 번째 섹션**으로 읽혔다. 제목 줄로 올려 `h1`과 나란히 뒀다 |
| **`자산 등록`을 그룹 머리글(투자 자산) 안에 두기 (Task 009 재개정)** | 두 그룹 중 한쪽에 속한 액션으로 읽힌다. 현금 자산을 등록할 때 투자 자산 머리글의 버튼을 눌러야 한다 |
| **그룹 제목을 격자지 배경 위 `text-lg` h2로 두기 (Task 009 재개정)** | 두 그룹이 똑같은 형태로 반복돼 "총 자산의 두 하위 분류"가 아니라 "같은 목록이 두 번"으로 보였다. 제목을 표면 안 머리글(합계 카드와 같은 규격)로 넣어 각 그룹을 한 장의 장부로 만들었다 |
| **그룹 건수를 머리글 오른쪽 끝에 우측 정렬 (Task 009 재개정)** | 장부 집계처럼 보이길 기대했으나, 바로 아래 `수량` 라벨·`›` 표식과 미세 라벨이 세로로 겹쳐 쌓이고 1280px에서는 제목과 700px 떨어져 홀로 떴다. 제목 옆(`투자 자산 4건`)으로 붙였다 |
| **1건짜리 현금 그룹만 머리글 없는 단일 행으로 축약 (Task 009 재개정)** | 건수는 등록·삭제로 계속 바뀌는 값이라, 건수에 따라 형태가 달라지면 같은 화면이 며칠 사이에 다른 화면으로 보인다. 형태는 그룹의 존재 여부로만 가른다 |
| **그룹 머리글에 `bg-grid` 밴드 깔기 (Task 009 재개정)** | 행 호버가 `hover:bg-grid`라 머리글이 **호버된 행**으로 보인다. 머리글은 흰 표면 + 아래 실선만으로 세운다(`Card` 머리글과 동일) |
| **자산 유형 토글을 낱개 알약 3개(`gap-2`)로 (Task 010)** | 테두리 3개가 따로 떠서 입력 필드가 세 개 늘어선 것처럼 보였다. 유형은 한 필드다 — 테두리를 공유하는 세그먼트로 합쳤다 |
| **선택 상태를 잉크 채움만으로 표시 (Task 010)** | 강제 색상(forced-colors) 모드에서 채움이 날아가면 어느 칸이 선택됐는지 남는 신호가 없다. 굵기(semibold ↔ medium)를 함께 걸어 형태로도 갈랐다 |
| **폼 6칸을 한 줄로 평평하게 나열 (Task 010)** | 375px에서 라벨-입력이 여섯 번 반복되는 벽이 된다. `자산 정보`/`보유 정보` 두 묶음으로 나누고 묶음 사이만 32px로 벌렸다 |
| **묶음 제목 없이 여백만으로 폼 나누기 (Task 010)** | 32px 간격만으로는 왜 여기서 끊기는지 말하지 못하고, 조건부로 사라지는 평단가 칸이 어느 묶음 소속인지도 알 수 없다 |
| **폼을 본문 폭(`max-w-3xl`, 768px) 그대로 쓰기 (Task 010)** | 1280px에서 티커 칸 하나가 728px로 늘어나 6자를 받겠다고 화면 폭을 다 썼다. 입력 폼만 448px로 묶었다(목록·카드는 그대로 768px) |
| **CASH에서 평단가 칸을 그냥 비우기 (Task 010)** | 제출 버튼이 70px 튀어 오르고, 칸이 사라진 이유를 화면이 말하지 않는다. 같은 자리에 이유 한 줄을 남겨 점프를 25px로 줄였다 |
| **조건부 필드를 높이 애니메이션으로 접기 (Task 010)** | §4에서 모션은 색·경계선 전이 150ms로 한정했다. 높이 전이는 `prefers-reduced-motion`에서 어차피 즉시 사라지므로 두 경로의 결과만 달라진다 |
| **모든 필드에 힌트 문구 달기 (Task 010)** | 네 칸 전부에 설명을 붙이면 폼이 1.5배로 길어지고 정작 에러 문구가 묻힌다. 설명은 예시와 검증 에러(§7)가 나눠 맡는다 |
| **수치 예시에 천 단위 쉼표(`1,000,000`) 쓰기 (Task 010)** | 쉼표는 입력하면 거부되는 문자다(`NUMBER_FORMAT`). 규칙과 다른 말을 하는 예시는 예시가 아니라 함정이다 |
| **flash 배너를 `h1` 아래에 두기 (Task 010)** | 위 16px·아래 24px로 여백이 비슷해 합계 카드와 뭉쳤고, 배너 유무에 따라 §6-2의 제목 아래 리듬이 달라졌다. 본문 맨 위로 올렸다 |
| **폼에 취소 버튼 추가 (Task 010)** | 파괴적이지 않은 폼이라 되돌릴 것이 없다. 헤더 워드마크·뒤로가기가 같은 일을 하고, 주 액션 옆 취소는 시선만 나눠 갖는다 |
| **상세 화면의 다섯 블록을 전부 같은 간격(16px)으로 쌓기 (Task 011)** | 조회·차트·시뮬레이터·수정·삭제가 균질하게 이어져 화면에 위계가 없고, 읽다가 그대로 손이 미끄러지는 자리에 삭제 버튼이 왔다. "저장되지 않는 것 / 저장되는 것"으로 갈라 40px을 벌렸다 |
| **상세 정보 6줄을 한 덩어리로 쌓기 (Task 011)** | Phase 2에서 뒤쪽 세 줄이 전부 `—`라 빈 값이 아니라 렌더 실패로 읽혔다. 실선 하나로 "내가 적은 값 / 시세가 채우는 값"을 가르고 이유 한 줄을 덧붙였다 |
| **현금 화면에도 평단가·취득원가 행과 평단가 차트를 그대로 노출 (Task 011)** | `avgPrice=1`은 저장상의 약속이라 화면에 나오면 오히려 오해를 만들고, `cost = 1 × quantity`라 보유수량과 같은 숫자가 두 번 찍혔다. 차트는 "현재 1"짜리 평단선을 그려 시그니처를 무의미하게 만들었다 |
| **예상 평단선을 방향과 무관하게 항상 현재선 아래에 긋기 (Task 011)** | 평단이 오르는(▲ +3,333) 경우에도 선이 아래로 가서, 스케일이 없는 이 플롯에 남은 유일한 시각 정보(방향)가 거짓말을 했다. 좌표는 고정하되 gain일 때만 위아래를 맞바꾼다 |
| **평단선 좌표를 실제 값에 비례해 계산 (Task 011)** | Task 025의 실시간 시세 차트가 들어오면 통째로 버려질 임시 스케일 로직이다. 방향만 맞추고 거리는 고정했다 |
| **시뮬레이터와 수정 카드를 테두리·배경색으로 구분 (Task 011)** | §2-3의 "유채색은 정보일 때만"을 깬다. 차이는 형태가 아니라 문장으로 말한다 — "결과는 저장되지 않습니다" 한 줄이 두 카드의 차이 전부다 |
| **시뮬레이터 결과를 입력칸 아래 실선 하나로만 구분 (Task 011)** | 같은 흰 표면에 이어져 입력의 세 번째·네 번째 줄로 읽혔다. 격자지 색 밴드에 담아 "답"으로 떼어냈다 |
| **카드 안 폼도 본문 폭(768px)을 그대로 쓰기 (Task 011)** | §6-3에서 이미 폐기한 것과 같은 문제 — 6자리 금액 칸이 700px로 늘어난다. 카드 안에서도 `max-w-md`로 묶는다 |
| **수정 제출 버튼을 폼 폭 전체(448px) 검정 솔리드로 (Task 011)** | 한 화면에 폼이 둘인데 한쪽만 풀폭 솔리드면 시뮬레이터의 `계산`이 부수적인 것처럼 보이고, 바로 아래 삭제 밴드까지 겹쳐 화면 하단이 무거워졌다. 풀폭 규칙(§6-3)은 화면 전체가 폼 하나일 때로 한정 |
| **삭제 버튼을 수정 카드 안 `저장` 옆에 두기 (Task 011)** | 파괴적 액션이 주 액션과 같은 줄·같은 표면에 온다. 카드 밖 실선 아래로 내보냈다 |
| **삭제 밴드 문구에 "복구할 수 없습니다"를 다시 쓰기 (Task 011)** | 확인 팝업의 고정 경고(ROADMAP 결정 #4)와 같은 말이 두 번 나오면 둘 다 안 읽힌다. 밴드는 용도, 팝업은 결과를 말한다 |
| **삭제 확인 제목에 조사를 붙여 "삼성전자를 삭제할까요?" (Task 011)** | 종목명 받침에 따라 을/를이 갈려 코드로 조사를 고르게 된다. 명사구(`{종목명} 삭제`)로 끊었다 |
| **없는 자산 안내를 `Alert`(error)로 (Task 011)** | Alert는 액션에 대한 피드백에 쓴다. 이건 화면이 통째로 비어 있는 상태라 총 자산 빈 상태와 같은 `Card` 골격을 쓴다 |
| **화면 문구에 내부 Task 번호 노출 ("실시간 시세 연동은 Task 025에서 진행합니다") (Task 011)** | 사용자에게는 존재하지 않는 어휘다(§7 — 사람이 쓰는 말로 쓴다). "시세를 연동하면 이 자리에 채워집니다"로 바꿨다 |

## 9. 후속 과제

- **웹폰트 자급.** 지금은 Google Fonts CDN에 의존한다. Capacitor 패키징(Phase 4) 시 오프라인에서
  폰트가 안 뜨므로, 그 전에 서브셋 폰트를 `frontend/public/fonts/`로 self-host 전환해야 한다.
- **다크 모드.** MVP 범위 밖(PRD 「MVP 이후 기능」에 설정/테마 제외 명시). 토큰이 `@theme` 한 곳에
  모여 있어 `prefers-color-scheme` 블록 추가만으로 확장 가능한 상태로 남겨둔다.
- **차트 시각화.** 자산 상세의 평단가 차트(§6-4)는 아직 **평단선만** 그린다 — 시세 선도, 눈금축도 없고
  두 선 사이 거리는 값과 무관한 고정값이다. Task 025에서 실시간 시세가 들어오면 세로축 스케일이
  생기므로, 그때 §6-4의 "방향에 따라 위/아래 두 좌표 중 하나" 규칙은 실제 좌표 계산으로 대체된다
  (뱃지·변화량 배치 규칙은 그대로 남는다).
- **시세 연동 후 걷어낼 문구 2종.** 상세 정보 카드 하단("평가금액·평가손익·비중은 시세를 연동하면
  채워집니다")과 차트 카드 하단("시세 차트는 시세를 연동하면 이 자리에 채워집니다")은 Phase 2 한정
  주석이다. 총 자산 합계 카드의 같은 성격 주석(§6-2)과 함께 Task 023·025에서 제거한다.
- **폼 제출 진행·실패 표시.** 등록 API(`POST /v1/assets`, Task 012·018) 연동 시 제출 버튼의 진행 라벨
  (`자산 등록 중`)과 폼 상단 서버 에러 `Alert` 자리가 필요하다. 둘 다 §6-1 인증 화면이 이미 정한
  패턴을 그대로 쓴다 — 새 규약을 만들지 않는다. 상태 추가 자체는 senior-frontend 몫이다.
